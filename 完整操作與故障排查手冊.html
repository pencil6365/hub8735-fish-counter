文件基準：2026/10/28。適用於 HUB8735_Fish_Transfer_20261028 搬機套件及其 GitHub 去除私人設定版本。實際新增的測試、模型及版本，應追加到專案現況；本文件不表示所有可能故障都已經發生或已被排除。

2. 系統怎麼運作

魚缸上方相機
  ├─ RGB 416×416 → 8735 的 AI → fish 框、信心分數 → 當前可見魚數
  └─ H.264 影像 → 加上框及數字 → 區域網路 RTSP → 手機/電腦播放器

USB Serial 115200 → 除錯訊息與每秒 JSON 計數

「在板上辨識」表示模型在 8735 上執行，電腦不必持續開著跑 AI。電腦仍用於準備、編譯、燒錄與觀察。想看到即時畫面，板子與播放器需要可互通的網路；只有插電且沒有網路時，不能從遠端播放器看到影像。

目前計的是每個畫面可見、符合門檻的魚框，不是魚缸真實總數，也不是魚游過一次就累加。五尾是初期需求，程式不會把數字硬截成五；超過時加上 CHECK COUNT，提醒檢查誤框或場景魚數。

3. 搬機前要準備

  1. Windows 11 64 位元電腦，至少 3 GB 可用空間；ZIP 本身約 810 MB，解壓及首次準備工具還會增加用量。
  2. HUB-8735_ultra、相機、可傳資料的 USB 線。充電線不一定能傳資料。
  3. 完整搬機 ZIP。不要只複製 .ino，也不要只下載 GitHub 的程式碼 ZIP 就以為包含全部工具。
  4. 官方回傳的魚模型 .nb 和轉檔報告；沒收到時先完成環境準備。
  5. 現場 Wi-Fi 名稱及密碼；GitHub 版需要自己補填。
  6. 要看影像時，準備支援 RTSP 的播放器，例如 VLC。要看 USB 訊息時，準備序列監控工具；可使用已安裝 Arduino IDE 的序列監控。這兩項與 USB 序列驅動未包入。

GitHub 若提供 Release 下載，請取其中完整搬機資產；一般的 Source code (zip) 只會包含儲存庫內檔案。模型待轉檔是原型狀態，即使名為 Release，也不表示板上 AI 已通過測試。

4. 解壓與首次開啟

  1. 把 ZIP 複製到另一台電腦。
  2. 右鍵 → 全部解壓縮，讓檔案直接放在 C:\Fish。
  3. 確認入口是 C:\Fish\00_START.cmd。若變成 C:\Fish\很長的資料夾名稱\00_START.cmd，請把裡面整套檔案移到短英文資料夾，再開啟。
  4. 不要在 ZIP 預覽內雙擊程式，否則同層檔案可能找不到。
  5. 雙擊 00_START.cmd，選 1。第一次要解開開發板與編譯器，請等候完成；不必用系統管理員權限去改整台電腦設定。
  6. 成功時應看到 ideasHatch:AmebaPro2、4.0.15-Release。

選單使用隨包的 Arduino CLI，設定放在 portable/runtime。不需要先安裝 Arduino IDE、Python、CUDA 或大型訓練環境。它只為自己的 PowerShell 程序設定執行參數及 C locale，沒有修改 Windows 全域執行政策或地區設定。

5. 選單每個選項做什麼

選項 做的事 是否改板子
1 解出與初始化離線開發板工具、列出套件 否
2 選取官方 .nb、複製入新韌體、啟用自訂模型程式 否，會改套件內的新專案副本
3 檢查模型、編譯、記錄來源與成品雜湊 否
4 核對成品、詢問 COM、輸入 FLASH 才上傳 是，覆寫板上現有程式

0 結束 否

所有較早的訓練 .cmd 都不是這個搬機入口。請優先從根目錄選單操作。

6. 官方轉檔結果要怎麼處理

官方申請網址：Ameba 模型轉檔。申請帳號由使用者本人保管，登入、驗證、密碼不應交給交接文件或 GitHub。

交接時已送出的設定：

設定 內容
模型類型 YOLOv7-TINY-Pytorch
上傳模型 delivery/fish_model_for_ameba.zip，內含 fish_reparam.pt
輸入 RGB，H=416，W=416
類別 1，class 0 = fish
量化申請 UINT8
校正圖 calibration_01.jpg 至 calibration_08.jpg，八張公開來源圖片

校正資料夾還有 09/10，屬使用者空缸圖片，先前沒有上傳。申請頁沒有顯示申請編號；mail-sent-ok 只能證明網頁回報送出，不是模型轉換成功。

收到信後：

  1. 核對寄件來源和申請內容，再依連結下載結果，不要執行來源不明的下載程式。
  2. 解開官方壓縮檔，保留原始下載檔、轉檔紀錄、設定與錯誤日誌。
  3. 找真正的 .nb。若只有錯誤紀錄，就表示尚無可用模型。
  4. 核對模型家族、輸入尺寸、RGB、量化、類別與輸出後處理。檔案能選進去不代表這些正確。
  5. 在根目錄選單選 2，選擇該檔案。確認設定符合後輸入 YES。
  6. 成功後新專案內應有 yolov7_tiny.nb 及 model-install.json。

不要重複送申請來「加速」未知排隊；先查收件匣、垃圾郵件及官方回覆。沒有轉檔完成時間承諾。

7. 設定 Wi-Fi、編譯

選 5 開啟 WifiCredentials.h，在雙引號之間填入現場 Wi-Fi 名稱及密碼，保留程式語法。請勿把密碼貼到公開 issue 或截圖中。若設定含雙引號或反斜線，需由熟悉 C++ 的人處理字串轉義，不要直接刪除符號。

GitHub 版本採占位文字，需填入後儲存關閉。先前私人搬機包含原設定，因此兩種版本可能不同；不要照舊截圖推測目前設定。

選 3 後，程式會檢查模型及安裝記錄，再編譯。成功應出現 編譯成功，尚未燒錄，並產生 portable/runtime/build/flash_ntz.bin 與 verified-compile.json。修改 .ino、.h、Wi-Fi 或 .nb 之後都要重新選 3。

8. 連板子、確認 COM 與燒錄

  1. 將板子接上電腦，觀察裝置管理員的「連接埠（COM 和 LPT）」。原機 COM3 只是歷史記錄，換機可能不同。
  2. 若不確定哪個埠，可比較插入與拔除時新增／消失的埠；避免拔掉其他設備。
  3. 若沒有新增 COM，先換可傳資料線及 USB 插孔，再查看裝置的硬體 ID，依晶片廠商官方來源取得對應驅動。不要猜測一定是某款 USB 晶片。
  4. 關閉 Arduino 序列監控及其他占用同一 COM 的程式。
  5. 確認願意覆寫板上現有程式，才選 4。
  6. 選單列出電腦 COM 名稱後，輸入實際板子的 COM，例如 COM5。列出的埠並非每個都是本板。
  7. 板子方向：鏡頭朝上，USB 接口朝下。按住左側較小的下載／功能按鈕，短按右側較大的 Reset，再放開左小按鈕。不同硬體修訂若按鍵位置不符，先核對板上絲印，不要盲按。
  8. 回到選單，輸入大寫 FLASH 才會開始覆寫；不要拔線、斷電或反覆按 Reset。
  9. 上傳工具回報成功後，短按右大 Reset 啟動新程式。

不要用 LED 是否變色作唯一判斷。 此板的下載模式燈色與長按秒數尚未建立可靠規則。下載操作靠按鍵順序與上傳回報確認；一般 Reset 為短按，不需要持續壓很久。

未取得完整板上 Flash 讀回備份。HUB8735_RTSP_Basic 是原純串流程式的原始碼副本，恢復時仍要重新編譯、上傳；不等同可完整還原板子所有舊資料的映像。

9. 開機、影像和數字怎麼看

序列監控設 115200。若監控工具不在搬機電腦上，需要另外準備；避免同時開兩個監控或一邊監控一邊上傳。

成功連上 Wi-Fi 時，Serial 會輸出 RTSP: rtsp://...。使用實際印出的完整網址與埠號，在同一區域網路的 VLC 等 RTSP 播放器開啟，不要硬套以前的 IP。

畫面文字：

  • Visible fish: N：目前畫面的有效魚框數。
  • fish XX%：模型信心分數，不是該魚存在的校準機率或整體準確率。
  • CHECK COUNT：數目超出初期預期五尾，需檢查是否重框或實際魚較多。
  • Fish model not ready | Count: N/A：目前是未啟用魚模型的版本，不能當作辨識成功。

每秒可能有以下 JSON，開機及 NN 除錯文字也會混在 USB Serial，接收端需要辨識合法 JSON 行：

{"schema":1,"uptime_ms":12000,"model_ready":true,"visible_count":2,"above_expected_max":false,"boxes":[]}

上例只示意欄位；正常兩尾結果通常會有相應框資料，不能用這行示意資料冒充實際輸出。model_ready=true 是編譯設定，不是模型語意正確或硬體驗證成功的證明。

10. 插電自動辨識與 Wi-Fi 的關係

搬機版把相機和 AI 初始化排在 Wi-Fi 前面，避免原草稿一直等 Wi-Fi 才開始 AI。Wi-Fi 不通時預期本機 AI/Serial 持續，RTSP 不會啟動；網路恢復後需重新開機，目前沒有背景自動重連功能。

外層 Wi-Fi 重試條件為 30 秒，但 WiFi.begin() 自己可能阻塞，因此不是嚴格 30 秒內完成。AI 在獨立串流任務中執行；Serial 計數要等 setup() 返回才進 loop()。實際無網路開機時間、資源使用、OSD 與串流啟動先後是否都正常，尚待 .nb 與實板驗證。

完成燒錄、模型放在 Flash 後，預期普通供電即可開機，不需要 SD 卡或連著訓練電腦。供電不足仍可能造成重啟，需用穩定電源和線材驗證。

11. 現場測試：依順序做，不只看一張畫面

測試 要記錄什麼 未通過時先看
空缸 是否出現假魚框、發生位置與光線 反光、裝飾、背景資料不足
1 尾 是否框住魚身和可見魚鰭、是否重框 門檻、魚太小、模型設定
2–5 尾分開游 每一畫面數量和肉眼可見數 漏框、框重複、縮放
靠近／遮蔽 只比較可見魚，不把完全遮住當已證實漏檢 NMS、資料不足
水面反光 不同燈光、角度、水面波動的誤框 先改善實體拍攝條件
斷電再上電 不按下載鍵能否自動啟動 供電、模型載入、Flash 設定
關閉基地台再開機 本機 AI 是否啟動、Serial 是否恢復 WiFi.begin 阻塞、啟動順序
連續運作 重啟、卡畫面、計數停止、溫度與耗電現象 電源、記憶體、網路與串流

建議記錄每個場景的時間、肉眼可見數、模型數、漏框／假框、門檻與程式版本，必要時保留經使用者同意的畫面。不要為了看起來數對而將輸出固定成五。

資料集的測試分數不能當作這個魚缸的驗收通過。先約定現場可接受的誤差，再用獨立場景測試；不要邊調門檻邊把同一組畫面稱作最終測試。

12. 已遇到的問題，以及已採取的處理

已觀察問題 原因／處理 尚存限制
很長路徑編譯出現找不到檔案、Insufficient memory 廠商舊工具處理長路徑有問題；要求根路徑短英文，選單超過 30 字元或有非 ASCII 會擋下 不代表所有「記憶體不足」訊息都是路徑問題
locale::facet::_S_create_c_locale name not valid 工具不接受繼承的 C.UTF-8；選單只在本程序設 LANG/LC_ALL/LC_CTYPE=C 不改 Windows 全域設定

上傳檔案起初失敗 當時由使用者開啟 Chrome 擴充功能的檔案網址權限後成功 新電腦瀏覽器自動化若遇權限，交由使用者處理；不需為燒錄隨意修改瀏覽器設定
串流編譯有 Failed to open directory/json 訊息 此次後續編譯及連結仍成功，退出碼 0 並產生韌體，保留日誌 AI 帶 .nb 的流程尚未證實，不能一律忽略同類錯誤

13. 常見或可能故障：依症狀排查

以下是排查方向，除前節列出的觀察外，不代表已在本板重現。

症狀／訊息 先做什麼 不要直接做什麼
雙擊後關閉或找不到 Start.ps1 完整解壓、確認入口與 portable 同層，保留黑窗錯誤 不要只複製 00_START.cmd
要求短英文路徑 放到 C:\Fish，避免桌面、雲端同步及多層資料夾 不要只解除檔案長路徑保護後繼續硬試
tar.exe 不存在／解壓失敗 確認是支援的 Windows、空間、ZIP 完整性、目標可寫 不下載來源不明的 tar 或 DLL
初始化中斷 先保留錯誤；選單再次初始化可能重解部分檔案。若環境損壞，備份自己補的 .nb、Wi-Fi 和日誌後，另解一份乾淨 ZIP 不刪原專案、照片或其他 Arduino15
.nb 尚未安裝／大小不符 找官方真正成品，核對回傳設定和格式 不更名 .pt，也不放官方內建通用模型冒充魚模型
已有不同模型，未覆寫 保留兩個版本，先核對 hash、來源和用途 不無條件覆寫舊模型
模型與記錄不同／專案改動 重新核對安裝記錄並編譯；保存正確模型 不刪保護記錄來硬燒
Use ... to stage .nb 或 FISH_MODEL_STAGED 錯誤 使用根選單 2 完整安裝 .nb，看 .ino 的模型呼叫 不只手動改 READY=1
缺少 library／找不到標頭 確認使用隨包 CLI 與同版本 BSP，初始化完整 不隨意升級 board package
編譯成功但沒有 flash_ntz.bin 保留完整輸出，視為不成功，查 postbuild 不拿其他資料夾的舊 bin 補上
COM 沒出現 換資料線/USB 埠，查裝置管理員與官方驅動 不先改波特率或清 Flash
Access denied／COM busy 關閉監控、播放器以外的序列程式、IDE 占用 不反覆拔插到其他設備
Upload timeout／一直等待 核對 COM、下載按鍵順序、線材及電源；保存日誌 不立刻用 Erase only 或亂改 Flash 位址
上傳不穩 先排線材/下載模式，必要時由熟悉者改較低上傳速率並記錄 不改 Serial 115200 來當上傳修復，兩者用途不同
開機亂碼 監控設 115200、確認埠正確，再觀察重啟 不把所有亂碼當 AI 故障
一直重啟／無輸出 穩定供電、短按 Reset、看最前面日誌、模型載入錯誤 不先重新訓練
Camera/stream link failed 核對 JXF37、相機連接、程序啟動先後，保留錯誤 通電時不要任意拔接相機排線
模型載入失敗／輸出數量異常 核對 YOLOv7-tiny、RGB、416×416、UINT8、單類別、輸出層及官方轉檔紀錄 不任意更改張量尺寸讓它「不報錯」
黑畫面／RTSP 無法播放 讀實際網址、同區網、連線隔離、防火牆與播放器支援；先查相機/RTSP 啟動訊息 不關閉整台電腦防火牆來碰運氣
有影像但沒框／N/A N/A 先查是否啟用魚模型；有模型再查 Serial、類別、門檻和場景 不宣稱沒有框就是沒有魚
空缸有魚／魚數過多 看反光/裝飾誤框、輸出類別與 NMS，收集實際背景資料 不硬扣固定魚數掩蓋誤判
小魚漏框／魚黏一起只一框 讓整缸合理填滿視野、改善光線、檢查遮蔽，補獨立俯視資料 不為數對而把同一魚框拆成多個
無 Wi-Fi 時沒畫面 本版預期沒有 RTSP；用 Serial 查本機狀態，網路恢復後重開 不把沒 RTSP 直接當 AI 沒啟動
新電腦無 GPU／Python 缺套件 燒錄選單不需要 GPU/Python；舊 PC 預覽和重訓才需要 不為燒錄安裝數 GB 訓練套件
舊 .cmd、YAML、train.txt 指到 Evans 這些是歷史訓練資料；重建 Python 環境並重新產生可用路徑 不全機搜尋取代或修改原資料

14. 為什麼不能直接改 READY，模型怎麼被放進韌體

.pt 是訓練框架權重；.nb 是此板推論引擎需要的轉換格式。重參數化把訓練網路整理成部署結構，仍沒有做板上量化驗證。

安裝時預期同時完成：

  1. 複製官方模型為新專案的 yolov7_tiny.nb。
  2. 設 FISH_MODEL_READY=1 與 FISH_MODEL_STAGED=1。
  3. 在 .ino 放入 detector.modelSelect(OBJECT_DETECTION, CUSTOMIZED_YOLOV7TINY, NA_MODEL, NA_MODEL);。
  4. 寫入 model-install.json 記錄 hash。

這是為了讓 BSP 的文字掃描和 C++ 條件編譯一致。安裝只檢查副檔名、大小、使用者設定確認與 hash，無法從檔案大小得知模型是否真的正確；完整編譯及硬體測試不可省略。

燒錄前會比對 verified-compile.json 的 .ino/.h/.nb 與輸出 bin 雜湊，並將核對過的 flash_ntz.bin 放到廠商工具使用的固定位置，再呼叫上傳器。請不要在此期間開另一份工程用相同工具目錄編譯或燒錄，避免共享工具檔案被更新。

17. 備份、更新、回復

每次換 .nb 或改設定，保留舊模型、官方回傳報告、model-install.json、編譯記錄及驗收結果，並以日期區分。不要將 Wi-Fi 密碼加入公開 Git 記錄。若要更新文件中的狀態，應寫明證據：例如「完整 AI 編譯退出碼 0」、「上傳工具回報成功」、「現場 3 尾測試通過」，不要只寫「完成」。

燒錄失敗先不要清整片 Flash；讀完整日誌、確認下載模式，再決定是否需重新上傳。若要回復純串流，先查看 project/HUB8735_RTSP_Basic、補本地 Wi-Fi、相同 board package 編譯，取得使用者確認才上傳。未測試的恢復流程不能當作一定可還原。
